# Inspect the finished Todo example

Use the private [`stele-examples`](https://github.com/jensvansteen/stele-examples) repository when you want to see the completed evidence layer before adding Stele to your own project. The example installs `stele-spec` from npm and imports no source from the Stele repository.

If you want to create the OpenSpec plan and implementation yourself first, use [Build a Todo feature with OpenSpec and Stele](/guide/build-todo). This page starts from the finished repository and focuses on reviewing the result.

## Run the end result

From a checkout of `stele-examples`:

```bash
npm ci
npm run todo:test
npm run todo:verify
npm run todo:dev
```

Open the URL printed by Vite for the plain Todo app. Inspect the OpenSpec and Stele files in the repository and generated reports on disk; the example has no verification dashboard.

The expected verification result is:

```text
OpenSpec strict validation passed
scenario execution passed: 5/5 passed
implementation verification pass: 4 requirements, 5 scenarios, 0 errors
deterministic validation passed
```

## Follow one behavior through the evidence layer

The Todo creation behavior demonstrates the complete chain:

1. The [OpenSpec Todo specification](https://github.com/jensvansteen/stele-examples/blob/main/apps/todo/openspec/changes/todo-app/specs/todo/spec.md) states the requirement and scenario in plain English and gives each a stable ID.
2. The [linkage plan](https://github.com/jensvansteen/stele-examples/blob/main/apps/todo/artifacts/linkage-plan.json) maps the requirement ID to a TypeScript declaration and the scenario ID to one exact named test.
3. The [Todo store](https://github.com/jensvansteen/stele-examples/blob/main/apps/todo/src/domain/todos.mts) places `@implements` beside the declaration that owns the behavior.
4. The [Todo tests](https://github.com/jensvansteen/stele-examples/blob/main/apps/todo/tests/todos.test.mts) place `@verifies` beside independently selectable tests.
5. `npm run todo:verify` invokes the installed Stele package. It runs those exact tests, invokes OpenSpec strict validation, resolves the planned anchors, and writes evidence under `apps/todo/artifacts/`.

## What to inspect

| Area | What it demonstrates |
| --- | --- |
| `apps/todo/openspec/changes/todo-app/` | Proposal, design, tasks, requirements, scenarios, and stable IDs |
| `apps/todo/artifacts/linkage-plan.json` | Planned requirement-to-code and scenario-to-test targets |
| `apps/todo/src/` and `apps/todo/tests/` | TypeScript implementation and verification anchors |
| `artifacts/test-results.json` | Exact scenario execution evidence generated by Stele |
| `artifacts/verification-report.json` | Deterministic linkage and freshness verdict generated by Stele |

Generated reports are local or CI output. The example's source, specifications, and linkage plan are committed inputs; the generated verdict remains reproducible from them.

When the chain is clear, return to [Getting started](/guide/getting-started#build-it-yourself-complete-project-setup) and apply the same structure to your project.
